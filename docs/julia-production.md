# SURE v8 Julia backend

The main application uses variant `v8`, revision `sure-v8-nr-calendar-2`.
The EMS preview is a separate model and release line. Its generated model,
42-parameter interface and datasets must not be substituted for the main app.

## Numerical contract

Julia 1.10.12 and the independent PySD 3.14.3 reference use the same v8
Vensim equations, six input CSVs and 53 calibrated assignments in 30 groups.
The solver uses Float64, annual Euler steps from 2011 through 2050 and
synchronous pre-step `DELAY FIXED` inputs. Dependencies and translator revisions
are pinned in `deploy/Dockerfile.julia-runtime` and `sure_julia/`.

V8 adds nonresidential PV, installation calendars, historical incentive
calculations and residential battery losses. Revision 2 treats PV building
stocks at or below `1e-10` as numerical zero in both tests of `PV removal
fraction`. The canonical Vensim source, preprocessed source and Python model
contain the same change. Calibration values and input data are unchanged.

The translator handles MIN/MAX and scalar lookup expressions in powers and
uses the audited v8 reduction sites. The calibration-only `GAMMA LN` objective
is outside the live simulation dependency closure. The Python calibration
translation still maps it to `scipy.special.gammaln`.

The runtime exposes 40 scenario parameters and 150 diagnostic outputs. Every
request owns its state, delays and caches. A Julia failure is reported and is
never silently retried with Python. The live engine is warmed before the HTTP
server becomes healthy, and subsequent requests reuse the compiled worker.

Each numeric cell must satisfy:

```text
abs(Julia - Python) <= 1e-10 * max(1, max_time(abs(Python))) + 1e-8 * abs(Python)
```

Years, labels and categorical values are exact. No invalid cells are excluded.
Physical gates check housing stocks and transfers, population conservation,
nonresidential PV stocks/orders, pending installations, and battery energy
balances. GMD rejects substantive negative weights and records tiny roundoff
exclusions explicitly. The source-zero correction does not relax tolerance.

its four ordinary sections were generated by Python/PySD, while its exploratory
results and general provenance still belong to v7/data-v2.0.0. It is not a native
Vensim reference certificate. Reviewed archive, native-input and sampling

Keep the exact 100 existing Latin-hypercube draws (17 parameters, uniform
marginals, seed 20261004) for all 128 policy mixes. Recompute the 12,800 outcomes

has 14,579 configurations, deduplicated to 14,571 simulations:

exploratory configurations.

## Gated regeneration

Use an isolated source checkout, the pinned runtime and a separate results
volume. Stage the reviewed native inputs, preview stores and uncertainty
samples explicitly. **Do not fetch the previous data release over these
inputs.** The preparation script validates the supplied input hashes and exact
sample identity; it does not download or overwrite them.

The operational repository documents the validation host and runtime setup.
Allocate 32 separate workers with CPU affinity and 128 GiB memory, one Julia,
BLAS and OpenMP thread per worker. Run detached so a client disconnection does
not stop the calculation. Pass the source checkout commit as
`SURE_SOURCE_COMMIT`; `/app` is the isolated checkout and `/runs` the results
volume. Then run inside that container:

```sh
sh scripts/prepare_model_release.sh v8-validated-NEW
```

The script requires a new run directory and records stage, resource usage and
exit status. Its gates are:

1. Reviewed inputs, identical uncertainty draws, software and source checks.
2. Julia generation, parameter API and small-model translation fixtures.
3. All 427 Python–Julia scenarios, including policies, uncertainty boundaries,
   all samples under minimum/maximum policies and v8 calendar/live regressions.
4. Exact state isolation, fresh processes, concurrent calls and crash recovery;
   then certification bound to the generated build and evidence hashes.
5. Re-exported calibration plots, checked against the validated baseline.
6. Identical serial/parallel 100-scenario pilots.
7. Full Julia regeneration, with checksummed checkpoints and no post-warmup JIT.
8. Independent Python regeneration and paired Julia comparison of all 1,771
   distinct ordinary-section scenarios (1,779 configurations).
9. Final schema, grid, finite-value, physical, sample-identity and resource audit.

No failed scenario is dropped. A resumed batch must have identical model,
parameters, sample and generation-code identities, plus verified output hashes.
The generated build manifest stays immutable; validation uses a separate
certificate. The script never publishes or deploys an application.

Before packaging, compare every published section cell to corrected Python and
measure the differences from the received preview, including hourly electricity:

```sh
python scripts/audit_v8_sections.py precomputed /runs/RUN/section-equivalence /runs/RUN/full /runs/RUN/section-audit.json
```

Stage the six reviewed native VDFX alongside the nine regenerated application
Parquets and the new v8 provenance. Package an immutable data release, update
`data-release.json`, and verify a fresh download. Runtime/data verification
requires the same generated equations, source files, calibration, parameters,
solver contract and dependency locks.

## Release and deployment

The image workflow tests Linux AMD64 and ARM64 independently: software tests,
Julia parameter API, numerical base/high/stock regressions, UI interaction,
worker reuse and HTTP startup. Both architectures must pass before publication.
Image dependency caches use `JULIA_CPU_TARGET=generic`.

Deploy only the environment/version authorized by the user, following the
private operations repository. The v8 main-app migration and its rollback must
also preserve the corresponding `SURE_VARIANT`. Deployment of the main app is
independent of the EMS preview.

## Scope and history

Acceptance certifies Python–Julia agreement and the stated physical checks;
it does not claim native Vensim equivalence or recalibrate the scientific model.
The previous v7 release/data and its evidence remain immutable. See
[the v7 report](validation/dispatch-correction.md) and
[the sampling procedure](policy-mix-100.md) for historical context. Earlier
models and investigations are retained in the Git history.
